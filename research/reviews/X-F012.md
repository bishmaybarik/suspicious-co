## Assessment

`ready_for_valuation` is defined upstream as source available + core variables
parsed + accounting identity within tolerance + no manual-review flag. Codex's
point is that this passes rows whose signs are impossible (38 rows with
negative total liabilities) and whose scale is unknown (92% have no units).
The accounting identity `assets − liabilities − equity ≈ 0` is satisfied by a
sign-flipped parse just as well as by a correct one, which is exactly how 38
negative-liability rows survive the gate.

## Tests I added

**Interaction with X-F017.** The two audit findings compound. Of the 560 ready
rows, 39 fail the sign gate and a further 70 carry a balance sheet shared with
another entity (see my review of X-F017, where all 33 same-URL clusters have
byte-identical evidence text). These sets barely overlap, so the usable ready
sample is materially smaller than 560 — closer to 460 once both filters are
applied.

**Direction of the bias.** Both problems are false positives: they inflate
apparent coverage rather than reduce it. For a net-worth aggregate this is the
dangerous direction, because the affected rows are not visibly missing.

**Negative equity is not obviously anomalous.** 24.4% negative equity in a
sample of foreign subsidiaries with intra-group debt funding is unremarkable —
holding companies capitalised with shareholder loans routinely show negative
book equity. Codex says this correctly and does not over-read it. My own
increment-1 note that Mauritius shows 53.8% negative equity (n = 13) should be
read with the same caution and I have downgraded it accordingly.

## Consequence

The recommended gate for the parent project is
`ready_for_valuation == 1` **and** `total_assets > 0` **and**
`total_liabilities >= 0` **and** the row's `*_evidence` text is not shared with
another target. Units must be resolved separately before any absolute
aggregation; the accounting identity does not constrain scale.
